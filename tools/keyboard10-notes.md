# keyboard10 — confirmed-size normal-hide handoff

Normal DidHide has a dedicated asynchronous entry; zero-duration lifecycle force-restore keeps its existing synchronous semantics. WillHide remains an asynchronous, whole-floating-view transform only. There is no snapshot, FBS transition context, synthetic keyboard notification, responder lookup for confirmation, inset mutation or added global hook. keyboard7 expansion acknowledgment and keyboard6 continuity algorithms are retained.

The normal path submits the original scene frame while retaining expanded host reference size, canvas and the collapsed visual transform. A main-thread bounded poll requires both applied scene frame and a PID-scoped client size acknowledgment. A request is one atomic 64-bit notify state containing a 32-bit sequence and two 16-bit quarter-point sizes. The reply echoes the complete word only after the app has exactly one foreground UIWindowScene and one visible normal-level UIWindow, and both window.bounds and scene.coordinateSpace dimensions match. Ownership is checked against the currently hosted PID; old generations/requests are rejected. No text crosses processes.

This proves WINDOW DIMENSIONS, not rendered pixels, a compositor fence, or completion of every custom view layout. It deliberately makes no claim that the video bounce is eliminated on device. Applications with multiple candidate scenes/windows or nonstandard hosting may never confirm.

Once both conditions match, a single main-thread performWithoutAnimation scope configures host reference/canvas and then clears the floating transform and restores normal frame/layout. layoutHostInCanvas skips pending recovery. FB completion only rechecks the same conditions; callback loss does not prevent a valid state-based handoff. Close/drag/rotate/lock/teardown cancel ownership. A fresh Show explicitly re-submits the expanded frame even when its target is unchanged and returns the visual transform; stale callbacks cannot clear it.

Sampling is bounded (120 main-queue samples at approximately 1/60 second, not a delay used as proof). If confirmation is unavailable, no blind normal-size handoff occurs: recovery attempts to re-submit expanded geometry and releases the visual collapse, retaining the original snapshot for a later hide/forced retry. A second rollback failure is logged and recovery state is retained; rendering in that exceptional condition is not guaranteed. No infinite pending/restoring wait is intended.

Host tests execute production scene, restore, floating, manager and event .inc files. The transport model separates scene submission, scene settings application, and client window size/request acknowledgment. Coverage includes old client dimensions after scene apply/callback, stale confirmation, one handoff, lost callback, same-target rapid show, lifecycle takeover, failure/retry, and timeout. Mutations explicitly check early clearing and intermediate host layout. UIKit, notify transport and actual remote surfaces are not device-tested by these tests. Legacy baseline failures are reported separately rather than concealed.

Build target remains RootHide iphoneos-arm64e, macOS 15 / Xcode 16.4 / iPhoneOS SDK 16.5 with the existing pinned Theos revision. No installation, respring, release, default-branch update or preference/default change is part of this work.
