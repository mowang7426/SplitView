# 空挂跟随设备方向：源码交接与待验矩阵

本轮只改源码；未编译、未运行测试、未安装、未注销、未操作屏幕。

## 本轮规则
- 一档空挂在设备横竖切换时跟随改变真实App场景方向；不是只旋转外框。
- 二档竖向空挂在设备转横屏时也转为横向；空间放不下转空挂图标，后续恢复从一档开始。回竖屏沿用临时图标恢复机制，满位仍保留图标。
- 某App通过工具条或空挂长按手动改过方向，该托管窗口生命周期内保留手动选择；恢复主窗、空挂、图标不清除。关闭后重新创建窗口才重置，不跨进程持久化。
- 当前自动跟随范围为低档空挂及旋转溢出图标；主窗、第三档和黄色最小化图标不在本轮新增范围。主窗跟随开关由另一个会话协调合并。

## 代码结构
- 每窗manualOrientationOverride记录手动选择；pendingDeviceOrientation/deviceLandscapeTarget合并连续设备方向变化。
- fitAfterContainerChange只记录最新目标；arrangeParked先调用applyPendingDeviceOrientation，再进行空间分配。
- 自动与手动复用rotateHostedCanvasToLandscape:automatic:真实场景回调；自动旋转不触发手动震动、不清空portraitSaved/rotationOverflow。
- 连接中或方向事务中等待原回调再次安排布局，不增加轮询，不以计时器冒充旋转完成。
- 横屏空间排布的二档victim转图标前重置thumbnailTier=0、thumbnailFree=NO、portraitTier=0、portraitCanvas=CGSizeZero；数量上限挤出不套用此分支。
- 旋转未受理保留旧窗口；已受理但回调校验失败仍沿用原关闭保护，不能宣称所有App支持旋转。

## 待用户允许后测试（目前均未执行）
1. 两个从未手动旋转的App放一档，设备竖→横→竖，确认内容方向和比例同步，未提前按旧画布收图标。
2. 只长按其中一个App手动改向；再旋转设备，确认该App保持选择，另一个仍跟随。恢复主窗/再次空挂/收图标后保持该例外。
3. 主窗旋转按钮手动改向后空挂，确认同样保持手动方向；关闭并重新建立窗口后恢复默认跟随。
4. 竖向二档遇设备横屏，有位保留二档横向；逐步增加其他空挂/图标直到无位，确认只收图标、不关闭场景；点击该图标恢复一档。
5. 上一步图标未点时转回竖屏：有位按一档恢复，无位仍图标；随后点击也是一档，不恢复旧二档大小。
6. 快速竖→横→竖，最后方向必须是竖；连接中旋转后等待就绪，不能永久停住排布。
7. 自动旋转中关闭/锁屏，旧回调不得复活窗口。未知App方向支持/回执失败不当作成功。
8. 合并二档自由移动后：自由二档旋转成功保留自由标记及相对位置；仅贴边排列二档会参与空间溢出。新增跟随开关关闭时不得提交自动方向请求。
